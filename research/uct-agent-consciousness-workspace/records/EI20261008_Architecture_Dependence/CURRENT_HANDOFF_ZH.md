# EI20261008：体验—能力的架构相对依赖

## 研究结果与边界

本轮针对用户提出的“人似乎没有体验就失去智能，但计算器仍能准确计算”的问题。先分开基础体验、特定体验内容、可用/报告通路和指定任务能力。C1/U1/P3保持；局部与整体实际过程可共存，不寻找开启体验的唯一中枢。

三种部件相同但接线不同的加法/乘法模型，正常均答对全部32个等概率任务；固定H寄存器为0后，成绩分别9/16、1、1；两条上下文通路都丢失后，任何只能读取x,y的算法最佳准确率都是9/16。通路的任务必要性不能从正常成绩跨架构直接搬运。信息可以换路径或换编码，但固定机制且无新增输入时，任务要求的区分不能从所有可用组织中消失还保证精确执行。

一般证明：N种不同完整任务响应，需至少N种可区分代码状态；均匀完整响应识别上界min(1,M/N)。不能把这个完整响应上界误当随机单题上界。H不是意识，R只报告任务上下文；没有证明特定人类感受存在/消失，没有计算体验量，没有证明当前助手有或无意识。

实际运行：扩展程序384个任务/夹持行、384个补码重编码检查、18组N/M下1224种有限编码，精确分数通过；紧凑check_core.py另实际运行通过并检查最小保留集合。无新人体/动物实验，无临床原始数据复算。远端紧凑正文和核心程序自包含，可下载扩展包还有全部逐项数据和长稿，两者不是同一字节版本。
