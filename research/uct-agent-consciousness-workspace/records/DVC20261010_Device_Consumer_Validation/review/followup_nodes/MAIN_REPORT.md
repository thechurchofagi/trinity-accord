## 3. Substantive compatibility findings

### Actual intake, contextual effect and retention

R156:SNAPSHOT_USE_LIMIT and R166:FINITE_TRACE_INSTALLATION_NONENTAILMENT already prevent matching present values or upstream interventions from identifying an installed mediator. R167:CONTEXTUAL_USE_CRITERION explicitly concerns contribution relative to a declared intervention closure; it does not by itself certify that a particular read occurred. R167's redundancy and compensation witnesses also prevent a single null or late endpoint from proving no prior use.

DVC's capture gates, surviving latches and immutable consumption snapshots are consistent applications. A closed gate can prevent a new capture while a consumer reads an old token. That token can be actually consumed while failing the intended current-probe condition. This is not a contradiction of a retained-use relation whose own target and interval are correctly specified. The same distinction is already explicit in R184:RTR and the TH stored/read/installed-decoder separation.

### Source and occurrence identity

IA20261008:TRACE_DOMAIN requires executed, independently grounded source-to-use paths. R177 keeps source, feature and use binding distinct. R185 requires an occurrence sort and grounded inclusions: equal data or endpoint tuples cannot establish numerical occurrence identity, and synchronization adds a relation without merging two copies.

DVC's source-origin and same-epoch requirements preserve those distinctions. The reference model stipulates true ancestry; a packet header, CSV row or software event is not self-authenticating physical evidence. A common snapshot can hold two specified earlier tokens without making them simultaneous source-port events or one common instantaneous world state.

### Time, complete state and physical intervention

R136, R176, TE and TO already distinguish information available after completion from information available before a fixed deadline, and source production from consumer use. OL fixes physically installed write ports, observation horizon and absence of unmodeled correction. UI includes retained randomness and mutable context in the sufficient state; CM makes pre-readout information exclusion a substantive premise.

DVC is compatible when its source issue, arrival, capture, commit and read events stay separate. An intended delay, a logged variable assignment, a physical actuator onset and a neural intake are different evidence layers. A finite reference schedule or manufacturer API description cannot certify the installed clock, physical branch or neural consumer. These are current application holds, not reasons to rewrite the mathematical conditional nodes.

### Named targets, C1 and U1

R146–R160, R166, R183, CORE and the later open bridges separate task behavior, intelligence profiles, actual constitutive relations, experiential structural counterparts, conceptual/report variables and independently named feelings. Complete-token C1 transport does not identify familiar mineness, agency or ownership from an engineer's input label. U1 supplies no new threshold based on gate status, synchrony, correctness, reset, report or instrument eligibility.

DVC's selected tactile PSE and discrimination parameter are therefore empirical/model-based coordinates with further interpretation obligations. An external shadow consumer does not become a human neural consumer because it operates during a human task. If the shadow has no causal path to the endpoint or its ancestors, it cannot supply the proposed human intervention; that is a boundary of the installation, not a claim that changing organization generally leaves complete experience invariant.
