# DVC20261010 装置消费者验证交接

本轮继续 MPC 与 SCU，没有重跑来源枚举，也没有把新装置检查点塞进已完成的 SCU 论文。稳定记录名为 `DVC20261010_Device_Consumer_Validation`，结果 `DVC-RESULT-v0.1.0`。候选保持禁用，UCT-MAP-v1.1.2 完成版不变。本子代理只写本 workbench；主代理负责按最新 expected-SHA 合并并核验 GitHub 与空间保存。

## 真正得到的结果

最有用的改进是把“实验员设了哪个输入门”与“指定消费者这一回真正读到了哪个来源事件”分开。关掉采样门不会自动清掉缓冲里的旧值。新探针已经发出，也不代表它在采样前到了真实端口。两个包都写着当前 epoch，仍可能换接来源或给旧事件改了标签。

模型完整枚举六个操作的 720 种全序：只有 6 种读到两个指定的新 token；360 种先读后提交而拒绝；另外 354 种读到了提交快照并给出同样的 1，但至少一路不是指定的新 token。这三类互斥且合计 720；不是实际设备错误率，更不是人体样本数。

人工证明给出两条可复用条件：缓冲内容是提交前最后一次未被清除的成功捕获；若端口有效区间为 `[a,b)`，采样闭孔径为 `[s-u,s+h]`，独立有界不确定性下必须且足够满足 `a_max+u <= s < b_min-h`。不同通道没有共同采样时刻时，仍可分别采样后保留同一次任务的两个实际来源，但要另行满足来源绑定、保留、原子提交、资源与截止时间条件。

## 执行与审查

代码实跑 PASS，零违例：720 个排序；4 组有无清空的门控配对；4,896 个时序参数/采样点检查；400 组非空安全窗口配对；108 个当前后果反馈时序实例；9 个保留反例。不同分母不合并成一个“总实验数”。

主代理提出的日志时刻倒退已修复：现在先对所有 lane 到达、再设门、再捕获；同一 tick 以 append 顺序为准。输出事件以实际读取事件为父节点。旧来源改 header 的例子保留了真的旧 origin。最终复查还补了 P 在 tick 8 被下一 token 替换，使声称的 `[6,8)` 有效区间与事件完全一致。最后一次修复只重跑原范围，没有扩大可选测试。

## 真实装置与体验边界

已选公开论文的 Touch X / Arduino rail 装置作接口背景，但我们没有访问、接线或部署该装置。M_D 是拟议的设备运动命令副本；P_E 是拟议的编码器/状态样本；两者都不能直接改名为人的神经运动命令或本体感觉消费者。厂商确实公开了 position/raw encoder 和 frame snapshot 语义，但论文实际用了哪些调用、固件、时间戳，以及影子端口是否存在，仍未核验。

尤其需要保留：如果影子消费者确实只读、没有通向运动、触觉、被试信息、注意、报告测量或分析的路径，仅改变它的门在同一因果模型里不会改变人的端点。它先验证数字装置自己的输入/读入合同，不能靠“旁边有被试”变成人体消费者干预。

今后独立拟定的体验相关主要端点是两次触觉比较的 PSE，不能倒称为原实验的预注册；独立拟合的 sigma 与原数据标注的 JND 分开保留，不默认为同一数量。agency、ownership 与熟悉我感 H 未测。C1 的结构对应只在独立实际完整 P/I/K 与来源/时序/读入关系同时成立后条件适用；本轮不增加基础体验门槛，也不指认 H、RetBind、唯一主体或当前助手的意识状态。

## 新颖性与下一步

旧值保留、竞态、快照、setup/hold 都是已有知识。MPC 的缺第四格和读入非辨识、SCU 的来源/载体/时序区分，以及 R173/R174/R187 的实际历史与端口前提已经扣除。净项是把这些约束落实为所选设备方向的 consumer-cell admission 修正合同及具体反例矩阵；适合保存研究检查点，不宣称新基础定理或另发一篇论文。

下一步应选择真实可访问的采集实现，确定实际命令源与状态端口、审读执行代码、测到达/采样/提交/读取事件和时钟误差。若无法获得装置，可以继续准备部署规范，但不能报告完成物理实验。全图兼容审计和实际证据缺口保持公开，QC10、IA-QC11、QC12、QC13 本轮不关闭。
