# Thought-experiment matrix

| Family | Fixed items | Varied item | Paired cases | What it tests | What it cannot establish |
|---|---|---|---|---|---|
| Ancestor / formation | current winner, target, `rho`, dispatch | losing route is newly formed live token vs identical stored description | both descriptions match, only one enters the resolver window | `LiveJoin` is occurrence-relative, not content identity | experience or `H` from formation alone |
| Abacus / calculator | displayed operands, final answer, timing | second candidate is read by the calculating transition vs mirrored to a display register | same answer and visible audit line in both | output and public log do not identify local consumption | actual hardware mapping without probing |
| Human-realized agent | two mutually exclusive team commands, clerk, overt action | clerk reads both before choosing vs stenographer copies team two while clerk reads only team one | same action, latency and transcript | local resolver read and dispatch mediation are separate | that any participant or aggregate has a particular experience |
| Copy / swap / memory | winner token, event clock, body/action target | live losing generator is swapped for a memory-only register with the same bytes | logs stay identical; validated resolver port changes only in live case | content equality does not preserve actual token participation | unique ownership or persistence of a subject |
| Bypass cut / replay | live tokens, `Z`, `rho`, target endpoint | cut `Z -> d`, then replay pre-cut `Z` at the same port | target dispatch disappears and returns only in mediated case | bounded resolver-to-dispatch contribution | universal necessity across every selector architecture |

The fixed/varied structure is constitutive of the thought experiments. A pair is invalid if the intervention changes bearer, target, route grain, token liveness, common event clock, or the meaning of the dispatch endpoint.
