# Prechallenge bound read-policy witness contract

Version `A4Y-PBRW-v0.1.0`. Status: disabled bounded application contract; not a general remote-attestation protocol, not a complete-controller certificate, not an actual installation and not a phenomenal bridge.

## 1. Fixed boundary and declared twin family

Retain A4X's one actual-process candidate `P`, interval `I`, complete-signature obligation `K`, event `e`, target activity `tau`, consumer occurrence `m`, named data ports `p_u,p_v`, live route occurrences `r_u,r_v` and full-factorial challenge family `J`. Add a mode-selection event, a read-policy state `z`, a policy map `rho(z)` giving the named ports that `m` will read, a challenge draw `d`, and an independently controlled witness path `w`.

The bounded rival family `T_1` contains deterministic challenge-indexed consumers which, on each admitted Boolean challenge row, read exactly one of `p_u,p_v` and apply either identity or negation to that value. Both port occurrences may be physically present and may be copied to a monitor. Thus apparent dual lineage, port availability or dual logging can remain fixed while `m` actually uses one port. Arbitrary controllers outside `T_1` are not claimed closed.

## 2. Candidate witness

Define `PBRW(P,I,K,e,m,z,rho,d,w;J)` by the conjunction:

```text
BEFORE AND BLIND AND BOUND.
```

1. **BEFORE.** The actual read-policy state `z` is fixed and witnessed through `w` before an independently generated, unpredictable-to-`m` challenge draw `d`; the order is `fix(z) < witness(z) < draw(d) < port-arrival < read_m < target-fix`. A record produced or alterable after the draw fails.
2. **BLIND.** From `fix(z)` until `target-fix`, the declared bounded causal inventory contains no path from challenge identity, arm label, trial order, shared random state, clock-coded schedule or supervisory cue to the policy dispatcher or to a mutation of `z`, except that the selected data values arrive through the named ports. A preloaded challenge-indexed table fails if it can receive the index.
3. **BOUND.** `z` determines the actual read set/order used by this occurrence of `m`; the witness path is tied to that consumer and event, detects substitution or post-witness mutation within the declared boundary, and is not merely a sidecar state or a log generated by the mechanism under test. Actual port occurrence, lineage and read remain separately required by A4X.

For a positive dual-read claim, independently establish `rho(z)={p_u,p_v}`. The disabled mode-safe application is:

```text
ConcurrentBCR2
AND A4X-BIND/LINEAGE/READ/FACTORIAL/CONTINGENT clauses for both ports
AND PBRW
AND rho(z)={p_u,p_v}
AND the remaining A4X alternate-path EXCLUSION clauses.
```

All terms share the same `P/I/K/e/tau/m/J` binding. `PBRW` operationalizes only A4X's hidden-mode part of `FROZEN/EXCLUSION`; it does not certify lineage, read, rescue fidelity, complete writer inventory, complete `K`, or any experiential interpretation.

## 3. Why one state value is not enough

- A state recorded before the draw but allowed to dispatch on a later challenge cue can encode the full challenge-indexed policy.
- A cue-blind state recorded only after the draw may already embody an adaptive choice.
- A timely cue-blind sidecar record does not constrain the actual consumer.

The smallest claim supported here is therefore a three-relation package—temporal precedence, cue isolation and consumer binding—inside `T_1`. This is **componentwise necessary and sufficient only for the declared finite separation**, not universally minimal evidence for arbitrary mechanisms.

## 4. Exact finite acceptance rule

The full-factorial target table is AND or OR. A challenge-indexed member of `T_1` may select a port and polarity separately for each row. A `PBRW`-admitted one-port member must use one fixed port/polarity mode on all rows. The exact result is:

- 256 challenge-indexed policies; 16 reproduce each target table;
- four fixed one-port modes; zero reproduce AND or OR;
- dropping BEFORE, BLIND or BOUND separately restores a 16-policy exact-mimic construction by, respectively, post-draw commitment, cue-indexed precommitment or sidecar substitution.

Passing the finite table plus `PBRW` excludes `T_1`; it does not prove that the alternate-path inventory is globally complete. A failed clause returns `NOT_INSTALLED_PBRW`, not nonparticipation, no mineness or no experience.
