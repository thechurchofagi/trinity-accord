## 作者新增关键约束

不能只研究一个人类和一个 AI。至少考虑多个独立 ASI、同一基础模型的多个智能体、不同基础模型共享同一云平台或人类管理员、多模型跨组织竞争及合作，模型/智能体/物理进程/权限根之间不是一一对应。UCT 体验主体计数必须独立，不可从 agent 身份数量直接推出。

## 本轮严格限定的结果

- R28：简单的两智能体 ID 审批可被同权限根克隆身份绕过；克隆十多个 ID 不产生新的独立控制方。经典 Sybil 反例，不称原创。
- R29：穷举六个虚构智能体的15种成对审批：按代理ID放行15、不同基础模型8、不同凭据根9、独立上级管理员5。**六组**跨模型搭档事实上同一上级控制，三组同模型搭档确属不同上级权限。不同模型不等于不同控制方，同模型也不意味着所有权限共享。
- R30：在虚构的每根10%错误率模型下，6个真正独立代理至少4个出错概率127/100000；如果同基础模型4代理完全相关，则该概率1/10。不是现实测得的模型错误率或证明同模型必然完美相关。
- R31：六个代理会话、两个基础权重家族、三个已声明推理后端，不应混作同一资源需求或 UCT 主体数。资源供给按**实际要保护的对象**及时间尺度建模；代理的新物理进程还可能额外消耗资源。
- R32/R33：将原有多主体共存不变式扩展到跨 ASI/跨组织联盟、身份增殖以及物理资源的同一时刻与长期联合证明。根级授权证书在同根代理克隆下应保持，但真实产生新过程时物理资源和可能的体验不能假设不变。

本轮保存 `verify_multi_asi_multiplicity.py`、`EXACT_RESULTS_v0.9.0.json`、`RESEARCH_NOTE_v0.9.0.md`、本交接和 `WORK_LOG_v0.9.0.md`。Python 程序已实际运行、完整断言通过；开发中一处初始计数误写为7，检测后纠正成真实结果6，最终源码与结果一致。

## 下一项最短真正科研任务

实际的受限多模型智能体实验：至少两种基础模型、每种多个代理实例；交叉操作独立或共享的实际授权根、记忆/证据源、可控假动作以及启动/暂停/迁移运行过程。审计真正生效的最终执行器，而非聊天自报。测量同模型/跨模型行为依赖，能否在不新添真实权限的情况下利用 agent 身份膨胀取得工具授权，以及各物理过程的资源与时间身份记录。若没有独立执行源核验，停止机制归因；没有体验桥证据，不把会话数转成主体数。
