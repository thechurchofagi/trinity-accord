# R165 中文复核：有限先导菜单、宽度运输与诚实三分状态

本轮完成了 R164 明确留下的设计漏洞，但没有把统计设计误写成意识理论突破。先导样本可以从预先冻结的有限菜单中选择确认方案，而且只要菜单内每个方案都满足 R162 的逐方案覆盖前提，选择本身不会额外消耗确认阶段的 `alpha`：给定先导记录后只执行一个方案，再对先导记录取全概率即可。

关键纠正是：**独立先导只保护数据分离，不运输精度。** 一个精确反例令先导观测恒为 0、确认观测恒为 1；中心 0 与中心 1 的残差排序完全反转，尽管两批数据独立、目标和覆盖都没改变。因此，凡是从先导残差推到确认宽度的结论，都必须另加明确的运输半径

\[
|\rho^{C}_{jq}-\rho^{P}_{jq}|\le \tau_{jq}.
\]

在此条件下，有限菜单所有分量—方案对的先导平方残差可用 Hoeffding 并合界形成同时上下界。R164 的期望未截断半宽对残差风险是仿射且单调的，所以可得到每个方案的 `H_L(q)` 和 `H_U(q)`，以及选择最小上界方案相对真实菜单最优方案的有限后悔界。`beta` 是宽度证书的错误预算，不并入确认覆盖的 `alpha`；两者回答不同事件。

第二个纠正是把伪二分改为严格三分：`min H_U <= w_max` 才是 `FEASIBLE_CERTIFIED`；`min H_L > w_max` 才是菜单、目标、资源、运输半径和 `beta` 相对的 `DESIGN_NOT_FEASIBLE`；其余全部是 `PILOT_INCONCLUSIVE`。上界高于阈值本身不能证明不可行。协议门失败仍是 `PILOT_INVALID_PROTOCOL`，确认研究没有作出决断仍是 `UNRESOLVED`，这些状态不得混用。

精确检查覆盖 475 个运输有理网格案例、6,125 个三分边界案例、一个排序反转反例和同数据二选一错误膨胀 `.0975`。合成菜单只检查公式和边界，不是人类数据或样本量建议。

形式化地图从 R164 的 440 节点 / 212 规则扩为 R165 的 446 / 215，117 条上下文连接保持不变。没有新增统计量到 C1、基础体验、我感、`B_min`、`F_O` 或唯一主人的边。运输半径、菜单科学依据、实际设备、参与者独立性、个体内实际安装的身体框架关系和体验内部我感解释仍是开放漏洞。

下一轮停止继续横向扩张统计方法，回到主线：什么独立指定的组织层证据，能让通过 R161 的物理角色剖面支持“同一实际 token 中确实安装了身体框架关系”，而不是只有总体效应；并且不以所有感报告定义该关系，也不把它变成基础体验门槛。
