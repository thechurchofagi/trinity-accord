# A4C — Same-bearer trace-content sensitivity in an embodied loop

## 1. Result

A4B jointly installed randomized formation and later retained-trace use in software, but its later endpoint simply copied one stored bit. A4C asks for a stronger organization-level witness: does formation content participate in a time-resolved body/action loop with the same bearer and consumer, and does a content swap move the endpoint in the direction predicted by that loop without writing the endpoint directly?

The answer is **yes for the declared embodied simulation**. In a balanced 32-trial installation, mean context-aligned final error was:

| Arm | n | Mean error |
|---|---:|---:|
| intact | 8 | 0 |
| same-bearer content swap | 8 | 3.9990234375 |
| block | 8 | 1.99951171875 |
| consumer-interface rescue | 8 | 0 |

Thus swap minus intact was `3.9990234375`, block minus intact was `1.99951171875`, and rescue minus block was `-1.99951171875`. Every action ledger exactly replayed to its endpoint. The same bearer and current consumer were retained in every trial. Formation and testing ran as separate operating-system processes.

This is a trace-content sensitivity result, not a phenomenal result. It neither identifies familiar mineness nor installs the complete physical organization of a robot or human.

## 2. Typed objects and chronology

For each context `c`, formation produces earlier calibration events, estimates the disturbance `b_c`, and writes a digest-bound trace `T_c` into one persistent carrier of bearer `P_sim`. At test interval `I0`, consumer `C_loop` receives exactly one value `z`, generates 12 actions and changes plant state through the declared update law. The endpoint is computed from the final plant state after those actions.

The types remain distinct:

- a numerical estimate is not its formation event or lineage;
- a stored trace is not current consumer use;
- current use is not a phenomenal interpretation;
- an abstract equation is not an installed run;
- this installed simulation is not a complete physical-signature description;
- an endpoint file is evidence about the run, not the run itself.

## 3. Exact mechanism

The controller uses

```text
u[t] = -k*x[t] - z,  k=1/2,
x[t+1] = x[t] + u[t] + b.
```

With the correct trace `z=b`, the state stays at zero. With a block `z=0`, it approaches context-aligned error `2`; with the opposite-context same-bearer trace `z=-b`, it approaches error `4`. A faithful rescue reinstates `z=b` at the named consumer interface while the native read remains blocked. These predictions were fixed before inspecting the executed outcomes.

The simulation is deliberately elementary. Linear feedback and motor adaptation are established antecedents. Human force-field work demonstrates formation of adaptive dynamics and contextual switching of learned internal models; it does not validate A4C's UCT interpretation or its software bearer. The project-level contribution is the typed same-bearer swap/locality contract and its bounded installation, not a new control theorem.

## 4. Why swap adds information beyond block

Block establishes that some delivered trace value matters. Swap adds content polarity: the alternative trace was formed earlier in the same bearer, passes the same schema and bearer validation, and drives the current action sequence in the opposite-context direction. This rules out the specific explanation that any nonzero retained object, regardless of content, is sufficient in the declared model.

It does not rule out every hidden route in an unmodelled physical realization. It also does not prove biological memory replay, ownership or familiarity.

## 5. Endpoint-only counterexample

The exact exclusion witness takes an intact action ledger and reports the numerical endpoint from a swap trial. It therefore matches the swap endpoint while its action replay yields the intact endpoint. It fails the declared no-direct-endpoint-write condition.

This establishes A4C-C2: an endpoint match or directional contrast is insufficient for route fidelity unless the event chronology and intermediate actions replay under the same law. It also explains why a successful DAG or a final score alone is not a theory proof.
