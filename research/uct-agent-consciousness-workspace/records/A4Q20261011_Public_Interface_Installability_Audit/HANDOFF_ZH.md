# A4Q 中文交接：公开接口可安装性与复合锚点路线

## 本轮实质推进

A4Q 把 A4P 的八项合同落实到一个公开可核查接口族：Universal Robots e-Series 的 RTDE、ROS 2 driver 与 UR Client Library。公开字段把 `actual_q`、实际TCP与时间戳列为控制器输出，把运动目标经反向接口送回控制器。由此必须区分：内部状态消费者 `rho_int`、外部命令 `rho_cmd`、以及 `actual_q -> 外部消费者 C_ext -> 反向命令` 的复合路线 `rho_ext`。

停用 ROS 命令控制器切断的是 `rho_cmd`，不能冒充 `rho_int` 的锚点输入切断。公开文档也没有给出把替代 `actual_q` 写进原生内部消费者的拼接端口。这只是对所查公开接口的有界结论，不排除厂商内部、研究或未来接口。

正面推进是 `rho_ext`：若把机器人、控制箱、外部PC和自定义消费者声明为复合承载者，就能在 `C_ext` 的同一个 `actual_q` 参数上做原生输入、切断和救援。但本轮没有实际机器人、外部跟踪器、固定软件/固件哈希、控制器完整清单或后仲裁事件来源见证；RTDE还允许跳过输出包而只发送最新值。因此A4P八项前提在实际token上的获准数仍为0，结论是 `NOT_INSTALLED`，不是路线不存在、装置无体验或C1失败。

## 初心与地图

本轮回答的是体验内部身体／行动我感所需的正面组织关系：当前行动是否真的以承载者锚点组织并由所选路线使用。它没有把控制表现、机器人身体、反馈、自我模型、报告、语言、整合、递归、预测准确或延续控制变成基础体验门槛。C1仍是意识特定解释性公设；只有实际同实例关系成立后，才可能经R159、C1/R157条件传递，`B_cf`、`H_cf`和报告桥接仍另行开放。允许机器人、PC、人类及更大系统的嵌套重叠过程，不选择唯一主人，也不判断当前助手有无意识或死亡恐惧。

正式图保持913节点、424条有效规则、261条非演绎语境边；A4Q增量0/0/0，727个待定对象停用、10条历史规则暂停。结构、代码及文档通过不等于理论真、实际安装或全历史深审。QC10、IA-QC11、QC12/13、R191归一化和深审缺口全部保留。

## 关键失败与下一问题

关键失败有四项：原生内部锚点拼接不公开；内部TCP读出不是独立外部几何；ROS命令资源独占不等于整个控制器／安全／URScript／物理路径闭合；网络时间戳和高频率不等于同周期消费—仲裁—执行见证。

下一具体问题：寻找真正公开的传感器—消费者内部拼接端口，或只实现一个严格有界的 `rho_ext` 试次包：外部跟踪固定几何、物理锚扰动、同参数切断／救援、反当前挑战、后消费者与后仲裁见证、完整控制器清单。任一合取不能同事件安装就停止，不进入 `H_cf`。
