# Common-control-cut protocol

1. Freeze bearer, actuator, plant, arbitration boundary, trial window, target and every admitted alternative writer.
2. List every accepted witness coordinate and its value, provenance, acquisition, transport, storage and acceptance path.
3. For power, reset, clock, bus, DMA, logger, firmware, maintenance and human-control roots, classify capabilities separately as observe, suppress, delay/retime, reset, replay, or arbitrary forge.
4. Draw directed influence paths.  A shared ancestor is a risk flag; do not call it a forge-capable cut without the capability evidence.
5. For every alternative writer, compute coordinate coverage and then test whether the covering controls are jointly compatible in one trial while satisfying cross-coordinate checks.
6. Attempt the hidden-writer twin under target cut.  If it reproduces an accepted complete vector, stop source attribution.
7. A candidate protected coordinate must be generated after final arbitration, source-specific, freshness-bound, outside alternative replay/reset/retime paths, and read through an acceptance path with the same protection.
8. Run negative controls: replay, clock rollback, reset, DMA injection, logger substitution, stale nonce, power fault and maintenance override.
9. Run faithful target cut and same-interface rescue.  Preserve A4D writer completeness and A4E current-event evidence.
10. Report only device/trial-relative source evidence.  Keep complete-K admission, retained-route identity and `H_way` validation separate.

**Stop rule:** graph separation, redundant logs, or a protocol self-attestation never suffices.  Stop if writer inventory is incomplete, capability composition is unknown, a target vector is replayable, or the protected coordinate/acceptance path is not physically verified.
